# 3 分钟演示脚本

演示前完成 README 的本地初始化、索引与 API / UI 启动。先确认页面显示 **演示模式**、**本地词法检索** 和分析日期 **2026-10-24**。这段脚本用于介绍项目；它本身不是测试结果。

## 0:00–0:25 · 说明问题与数据

“SupplyLens 是一个采购到货分析原型。所有订单和 SOP 都是合成数据。我想解决的是：把分散在订单、物流和收货记录里的信息，整理成能核对依据的异常报告。当前展示无密钥的确定性演示工作流。”

展示页面模式、日期、订单选择器。

## 0:25–1:20 · 一笔存在异常的订单

选择 `PO-1001`，点击“分析到货情况”。

依次展示：

1. 订购 1000，已收 600，未收 400；承诺日期 10 月 22 日，相对 10 月 24 日逾期 2 天。
2. 到货异常如何关联未收批次与物流记录。
3. “来源与依据”中的记录 ID 和原始字段。
4. “工具调用”中的实际参数与结果。

“这些数量和日期由代码从数据计算。模型或工作流负责调用工具，处理建议从检索到的 SOP 原文中选择，事实和跟进草稿由程序生成。”

若实际结果与上述预期不一致，先排查数据日期和初始化状态，不要继续按预设台词宣读错误结果。

## 1:20–1:55 · 展示判断边界

选择 `PO-1006`，展示已收齐订单不会继续触发当前到货异常。

再选择 `PO-1009`，展示缺少 ETA 被列为信息缺口。可补充 `PO-1008`，说明“已有延期证据”和“仍然缺少部分信息”可以同时存在。

“没有证据时，系统应该告诉用户还缺什么，而不是硬给出一个确定的延期结论。”

## 1:55–2:30 · 多轮追问与报告

重新分析 `PO-1001`，输入：`帮我写一份供应商跟进建议`。

展示当前订单上下文、建议与 SOP 来源，再下载 Markdown。

“这里生成的是跟进草稿，不会联系供应商。报告和工具轨迹可以分别检查。”

## 2:30–3:00 · 解释真实模型模式与验证

“Cloud 模式才会接入真实模型进行工具选择，并使用云端 Embedding。当前 30 个固定验收案例全部通过，包含 5 个故障注入，但没有调用真实云模型。Cloud 路径有 14 项脚本化模型协议测试，以及 1 项真实 SDK 配合模拟 HTTP 传输的测试，覆盖两轮工具调用与用量解析。真实云端效果仍需配置密钥后单独评测。”

只展示当前已运行的测试或评测产物。未配置密钥时直接说明 Cloud 评测未运行，不展示合成成绩。

## 录制前自检

- 固定分析日期与数据版本，确认样例订单结果。
- 页面与终端不露出 `.env` 内容或密钥。
- 检查工具轨迹能展开、Markdown 能下载、多轮追问指向正确订单。
- 录制结果应反映实际页面；出现失败可保留并解释，不后期改写业务数值。
